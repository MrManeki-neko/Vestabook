# Plan: Vestabook Remote — installable PWA for Android + iPhone

## Goal
Replace the placeholder home page with a mobile-first, installable PWA that lets Matt
(Android/Chrome) and his wife (iPhone/Safari "Add to Home Screen") see what's on the board
and control it: pick a book, toggle random mode, pause/resume. Cool split-flap "Vestaboard"
aesthetic. No new database — the PWA is purely a client of the existing endpoints.

## Existing features the PWA must surface (all already built)
- Live current frame: 6 lines × 22 chars (`/api/preview`, computed from elapsed time)
- Book library auto-discovered from `content/*.txt` (paradise_lost, moby_dick, inferno)
- Modes: auto-cycle (default), single book forced, random (`/api/control?book=|random=`)
- Pause / resume without losing place (`/api/control?pause=`)
- Quiet hours (board sleeps on a daily schedule; exposed via preview headers)
- Dongle-secret auth for control; control changes commit `config/state.json` to git →
  Vercel redeploy → **changes take ~15–30 s to apply** (UI must communicate this)

## Architecture decisions
- **New `GET /api/status`** (no auth, like preview): one JSON payload the UI can render from:
  ```json
  {
    "bookId": "moby_dick",
    "frameIndex": 123,
    "totalFrames": 4567,
    "frame": ["6 lines", "..."],
    "mode": "cycle" | "single" | "random",
    "paused": false,
    "quietHours": false,
    "intervalMinutes": 5,
    "books": [{ "id": "moby_dick", "title": "Moby Dick", "frames": 4567 }]
  }
  ```
  Titles are derived from ids (`snake_case` → Title Case). Reuses `getCurrentFrame`,
  `getState`, `isPausedNow`, quiet-hours helpers — no logic duplicated.
- **Control from the client**: the PWA calls the existing `/api/control?...&dongle=<secret>`.
  The dongle is entered once in a Settings sheet and kept in `localStorage`. No new auth.
- **Pending state**: after a control call succeeds, show "Applying — the board updates in
  ~30 s" and poll `/api/status` until the mode/pause reflects the change (or 90 s timeout).
- **PWA plumbing**: `public/manifest.webmanifest` (standalone, dark theme), icons
  (192/512 maskable PNG + 180 apple-touch-icon, generated by script from an SVG source),
  minimal `public/sw.js` (cache-first app shell, network-only for `/api/*`), registration +
  iOS meta tags in `app/layout.tsx`.
- **UI look**: dark room, the board front-and-center as a 6×22 grid of split-flap tiles
  (rounded dark tiles, centered hinge line, monospace, amber-on-charcoal), subtle flip
  animation when content changes. Below: status chips (book, frame x/y progress bar,
  PAUSED / QUIET HOURS badges), then big touch controls.
